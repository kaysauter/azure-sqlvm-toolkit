AzSQLVMKit follows convention over configuration. You provide the project identity, and the toolkit derives the resource names.

## Minimal Config

```yaml
project:
  name: "sqlvm-demo"
  environment: "dev"
  location: "Switzerland North"
  uniqueSuffix: "demo01"
```

Required:

- `project.name`
- `project.location`

Recommended:

- `project.environment`
- `project.uniqueSuffix`

If `project.uniqueSuffix` is omitted, the toolkit derives a stable short suffix from the project name, environment, and location.

## Generated Names

For the sample config, `-Plan` resolves names like:

| Field | Example |
| --- | --- |
| `ResourceGroupName` | `rg-sqlvm-demo-dev` |
| `StorageResourceGroupName` | `rg-sqlvm-demo-dev-storage` |
| `KeyVaultName` | `kv-sqlvm-demo-dev-demo01` |
| `StorageAccountName` | `stsqlvmdemodevdemo01` |
| `VMName` | `vm-sqlvm-demo-dev` |
| `ComputerName` | `sqlvmdemodev` |
| `VnetName` | `vnet-sqlvm-demo-dev` |
| `SubnetName` | `snet-sqlvm-demo-dev` |
| `NsgName` | `nsg-sqlvm-demo-dev` |
| `BastionName` | `bas-sqlvm-demo-dev` |

`-Plan` also shows each name source:

- `derived`: created from the project settings
- `explicit`: read from the legacy config shape
- `override`: set under `naming.overrides`

## Overrides

Use overrides when you need exact names or want to reuse existing resources:

```yaml
naming:
  overrides:
    resourceGroupName: "rg-my-existing-lab"
    keyVaultName: "kv-my-existing-lab-42"
    storageAccountName: "stmyexistinglab42"
```

Storage accounts and Key Vault names are globally unique in Azure, so these are the most common override targets.

## Optional Settings

Only include values that you want to change:

```yaml
credentials:
  username: "azureadmin"

vm:
  size: "Standard_DS13_V2"

storage:
  skuName: "Standard_LRS"
  driveLetter: "Z"

network:
  publicIp:
    enabled: false

bastion:
  sku: "Basic"
  subnetAddressPrefix: "192.168.2.0/24"

keyVault:
  useRbacAuthorization: true
```

For Bastion SKU choices and practical examples, see [Azure Bastion](/azure-sqlvm-toolkit/bastion/).

## Legacy Configs

Existing explicit configs still work:

```yaml
resourceGroup:
  name: "my-rg"
  location: "Switzerland North"

keyVault:
  name: "kv-my-demo-01"

storage:
  resourceGroup: "my-storage-rg"
  accountName: "stmydemo01"
```

New users should prefer the sparse `project:` shape.
