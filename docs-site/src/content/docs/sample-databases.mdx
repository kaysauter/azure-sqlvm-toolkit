title: Sample Databases
description: Optional allowlisted sample databases that AzSQLVMKit can download and restore.
---

AzSQLVMKit can optionally install sample databases during deployment.

Use this for labs and demos where you want a SQL Server VM with realistic data already restored. The feature is opt-in and uses a code-defined allowlist; arbitrary download URLs are not accepted.

Please credit the people and organizations who publish these samples. The toolkit makes installation easier, but the sample databases belong to their respective publishers and contributors. See [Third-party Notices](/azure-sqlvm-toolkit/third-party-notices/) for project, creator, source, and license links.

Some samples are large. Downloads are stored on the VM under `C:\SQLSampleDatabases`, extracted archives may temporarily consume additional VM disk space, and restored databases consume SQL Server data/log disk space. Manually uploaded `.bak` files that you place on the mounted Azure Files share also consume Azure Files storage. Plan both VM disk space and file-share capacity before enabling larger samples.

## List Available Samples

```powershell
Import-Module .\AzureSqlVmToolkit.psd1 -Force
Get-AzureSqlVmToolkitSampleDatabase
```

The `Name` column is the value to pass to `-InstallSampleDb`.

## Install A Sample

Preview first:

```powershell
New-AzureSqlVmToolkitDeployment `
  -ConfigFile .\config.local.yaml `
  -SecurityAssessmentAdvice `
  -GeneratePassword `
  -Plan `
  -InstallSampleDb AdventureWorks2022
```

Then run the Azure-aware dry run:

```powershell
New-AzureSqlVmToolkitDeployment `
  -ConfigFile .\config.local.yaml `
  -SecurityAssessmentAdvice `
  -GeneratePassword `
  -WhatIf `
  -InstallSampleDb AdventureWorks2022
```

Deploy with the sample database:

```powershell
New-AzureSqlVmToolkitDeployment `
  -ConfigFile .\config.local.yaml `
  -SecurityAssessmentAdvice `
  -GeneratePassword `
  -InstallSampleDb AdventureWorks2022
```

You can pass multiple values:

```powershell
New-AzureSqlVmToolkitDeployment `
  -ConfigFile .\config.local.yaml `
  -SecurityAssessmentAdvice `
  -GeneratePassword `
  -InstallSampleDb AdventureWorks2022, StackOverflowMini
```

## Runtime Behavior

The sample database installer runs inside the VM after guest setup and after the restore helper is uploaded.

It:

- downloads selected sample files to `C:\SQLSampleDatabases`
- extracts `.7z` files when needed
- imports `dbatools`
- skips restore when the target database already exists
- restores missing databases to the local SQL Server instance

The built-in sample installer does not download backups to the Azure Files share. It uses VM-local storage for downloads and extraction. The existing `restore-databases.ps1` helper is different: it restores `.bak` files that you place on the mounted Azure Files share, so those files consume file-share storage.

This is intended to make reruns idempotent for the common case. It does not verify or repair drift inside an existing sample database.

## Security And Licensing

Only allowlisted sample names are accepted. This avoids turning the deployment command into an arbitrary remote-download executor.

Before deploying a sample, review:

- publisher and download source
- license and attribution requirements
- checksum or integrity guidance from the publisher
- SQL Server version compatibility
- VM disk space
- Azure Files capacity when you manually store backup files on the mounted share
- Azure runtime cost while downloading and restoring

Sample data is useful for demos, but it is still third-party content unless it comes from Microsoft. Treat it as external input and do not add production secrets or private data to the sample restore flow.

The current toolkit does not verify sample database file hashes. For production-grade reproducibility, add publisher checksums or an internal artifact mirror before depending on these downloads.
