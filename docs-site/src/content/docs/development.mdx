## Local Files

Use ignored local files for environment-specific settings:

- `config.local.yaml`
- `*.local.yaml`
- `*.local.md`
- `.env`

Do not commit secrets, generated cost notes, or screenshots that reveal Azure account details.

## Checks

```powershell
.\scripts\Test-Local.ps1 -ConfigFile .\config.local.yaml
```

This is the minimum check before publishing module, script, config, or docs changes.

The public module surface lives in `AzureSqlVmToolkit.psd1`, `AzureSqlVmToolkit.psm1`, and `Public/`. Reusable validation, naming, output, password, role-assignment, reconciliation-result, deployment, and guest-script helpers live in `scripts/`. Focused Pester tests live in `tests/`.

## Docs

The published docs live under `docs-site/`.

```bash
cd docs-site
npm run build
```

## GitHub Actions

- `Deploy docs` builds and publishes the documentation site.
- `Test toolkit` validates the PowerShell script, common module, tests, sample config, docs dependency audit, and docs build.
- `Release toolkit` validates version metadata, runs local checks, builds docs, packages the module, and creates a GitHub release from a matching `vX.Y.Z` tag.

## Release Work

Keep `VERSION`, `AzureSqlVmToolkit.psd1`, and `CHANGELOG.md` aligned. See `RELEASE.md` for the release checklist and nightly snapshot guidance.
